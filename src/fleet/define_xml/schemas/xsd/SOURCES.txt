CDISC ODM 1.3.2 + Define-XML 2.1 schema set
===========================================

Fleet validates generated define.xml against these schemas
(fleet.define_xml.xsd.validate_define_xml).  Vendored from CDISC's own
public repository:

    https://github.com/cdisc-org/data-definition-engine  (MIT licence)
      schemas/define/2.1/  ->  define/2.1/
      schemas/odm/1.3.2/   ->  odm/1.3.2/

The upstream MIT licence text is in LICENSE-CDISC.  xml.xsd, xlink.xsd and
xmldsig-core-schema.xsd are W3C schemas, redistributed as CDISC ships them.

Layout matters as much as content: the Define-XML schemas import ODM by
relative path (../../odm/1.3.2/ODM1-3-2-foundation.xsd), so the two
directories must stay side by side exactly as published.

    define/2.1/   define2-1-0.xsd (root), define-extension.xsd,
                  define-ns.xsd, define-enumerations.xsd,
                  xlink.xsd, xml.xsd, xmldsig-core-schema.xsd
    odm/1.3.2/    ODM1-3-2.xsd, ODM1-3-2-foundation.xsd,
                  xlink.xsd, xml.xsd, xmldsig-core-schema.xsd

CDISC copyright headers inside each file are retained unmodified.

DefineSpecGenerator validates against these schemas on every generate()
and to_xml_string() call; pass validate_xml=False to bypass.

Override the location without reinstalling Fleet:

    export FLEET_DEFINE_XSD=/path/to/schemas
