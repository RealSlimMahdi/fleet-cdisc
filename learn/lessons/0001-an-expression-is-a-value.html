Lesson 01 · Polars in Fleet

An expression is a value

Why every function in fleet/adam/utils.py returns pl.Expr, and never receives a DataFrame.

Time 30 minutes Polars 1.41.0 Mission read adam/utils.py and explain every expression Card Expressions and contexts

There is one idea behind the whole of Polars, and therefore behind the whole of Fleet. A derivation is a value you can hold in a variable. Once that lands, the shape of Fleet stops being a design choice and starts being the only sensible option.

01What SAS will not let you do

In SAS, a derivation cannot exist on its own. This is legal:

But chg = aval - base; is a statement. It only means something inside a DATA step. You cannot put it in a macro variable and get back a derivation. You can put the text in a macro variable, which is why every SAS shop ends up with macro code that pastes strings together. Text is not a derivation. Nothing checks it until it is pasted in and run.

Why this matters for Fleet. A tool that stores derivations as text has to re-parse them, and cannot answer "which columns does this read" without guessing. Fleet answers that question exactly, because it holds objects, not strings.

The definition

The Polars user guide calls an expression "a lazy representation of a data transformation". Lazy means nothing has happened yet. The object describes work. It does not do work.

This is the part that has no SAS equivalent. chg_expr is a normal Python value. You can put it in a list, return it from a function, store it in a dictionary, pass it to another function, or reuse it in five different pipelines.

03A context is where the expression runs

An expression needs somewhere to run. That place is called a context. There are four you will meet in Fleet:

ContextWhat comes backClosest SAS
df.select(...)Only the columns you namePROC SQL select list
df.with_columns(...)Everything you had, plus the new columnsDATA step assignment
df.filter(...)Same columns, fewer rowsWHERE or subsetting IF
df.group_by(...).agg(...)One row per groupPROC SUMMARY

Keep this. The full table, with the rules and the traps, is on the Expressions and contexts reference card. Print that one. You will not print this lesson twice.

04Same expression, two contexts, two answers

This is the point that proves the expression is not the computation. Take a five-row ADLB and one expression, pl.col("AVAL").mean().

select

mean_expr = pl.col("AVAL").mean()
adlb.select(mean_expr)
shape: (1, 1)
┌──────┐
│ AVAL │
│ ---  │
│ f64  │
╞══════╡
│ 36.2 │
└──────┘

with_columns

adlb.with_columns(
    mean_expr.alias("MEAN"))
shape: (5, 6)
│ ... ┆ AVAL ┆ MEAN │
╞═════╪══════╪══════╡
│ ... ┆ 30.0 ┆ 36.2 │
│ ... ┆ 45.0 ┆ 36.2 │
│ ... ┆ 52.0 ┆ 36.2 │
│ ... ┆ 28.0 ┆ 36.2 │
│ ... ┆ 26.0 ┆ 36.2 │

One expression. One frame. Five rows on the right, one row on the left. The expression did not decide that. The context decided it.

In SAS terms

The left is PROC MEANS. The right is PROC SQL remerging a summary statistic back onto the detail rows, or a MERGE of a summary dataset back onto the original. Same statistic, different shape. In SAS you choose the shape by choosing a different procedure. In Polars you choose it by choosing a different context, and keep the same expression.

Look at what is missing. There is no DataFrame argument. There is no return of data. The return type is pl.Expr. This function cannot compute a change from baseline, and is not trying to. It builds a derivation and hands it back. Someone else supplies the data and the context.

That someone else is _chain(), in src/fleet/core/_verb_mixin.py:

There is the context: with_columns. Every Fleet verb you have ever called ends here, adding its expressions to a growing plan. And still nothing runs, because _lazy is a LazyFrame, not a DataFrame. Work happens in exactly one place, to_frame():

The whole architecture, in one sentence

A Fleet verb chain is not a sequence of DATA steps. It is one DATA step that you are still writing. to_frame() is the run;.

This also explains two things you have probably noticed and not questioned. Fleet can tell you that a column is missing before collecting anything, because it can ask an expression which columns it reads. And Fleet can record lineage without you logging anything, because the expression object is still available to inspect after the verb has returned.

07Drill

Answer from memory. Do not scroll up. Each question locks after one click, because guessing until the box turns green teaches nothing.

  1. This line runs. What now exists in memory?

    base_expr = pl.col("AVAL").max().over("USUBJID")

    An expression is a lazy description. No frame was named, so no data could have been read. Polars will not complain about a missing column either, because it has not yet been shown a schema.

  2. ADLB has five rows. What do these two lines return?

    adlb.select(pl.col("AVAL").mean())
adlb.with_columns(pl.col("AVAL").mean().alias("MEAN"))

    select returns only what you asked for, and a mean is one value. with_columns must match the original row count, so the single value is broadcast down all five rows. Same expression, different context.

  3. Why can this Fleet function work without a DataFrame argument?

    def chg(aval="AVAL", base="BASE", target="CHG") -> pl.Expr:
    return (pl.col(aval) - pl.col(base)).alias(target)

    The return type says it: pl.Expr. The function is an expression factory. Data arrives later, when a context in _chain() runs the expression against a real frame.

  4. This is Fleet's _chain(). When does the arithmetic actually happen?

    new._lazy = self._lazy.with_columns(list(exprs))

    _lazy is a LazyFrame. Calling with_columns on a lazy plan extends the plan and returns a new plan. The only collect() is in to_frame(). That is why a chain of twenty verbs costs nothing until the last line.

  5. Fleet's baseline(). There is exactly one baseline record per subject and parameter. So why is .max() in there?

    pl.when(pl.col("ABLFL") == "Y")
  .then(pl.col("AVAL"))
  .otherwise(None)
  .max()
  .over(["USUBJID", "PARAMCD"])

    The when / then / otherwise(None) blanks every non-baseline row. Inside each subject and parameter, exactly one value survives. Aggregations in Polars skip null, so max() of one surviving value and four nulls is that one value. max() is not picking a maximum here. It is picking the only one left. This is a common Polars idiom and you will see it again.

08Say it without looking

Close the lesson and answer out loud. Retrieval is what makes this stick, not rereading.

Name the four contexts, and what each returns.

select: only the columns named. with_columns: everything, plus the new columns. filter: same columns, fewer rows. group_by().agg(): one row per group.

What does print(pl.col("AVAL") - pl.col("BASE")) show, and why?

[(col("AVAL")) - (col("BASE"))]. It shows the plan, not a result, because an expression is a description of work and no context has run it.

Where, exactly, does a Fleet pipeline do its work?

In to_frame(), which calls self._lazy.collect(). Every verb before that only extends a lazy plan.
