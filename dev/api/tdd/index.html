    Trial Design Domains API¶

    fleet.sdtm.design ¶

    Study design aggregate — define the trial design once, derive every domain.

    StudyDesign is the single typed source of truth for a study's structure: elements, arms (as ordered element paths), visits, criteria, and summary parameters. Every Trial Design domain (TE, TA, TV, TS, TI, TD, TM) is derived from it, so TAETORD ordering, element/epoch duplication across arms, and cross-domain FK consistency fall out mechanically instead of being hand-maintained per row.

    Usage::

    import fleet

design = fleet.StudyDesign(
    study_id="CDISCPILOT01",
    elements=[
        {"etcd": "SCRN", "element": "Screening", "tedur": "P14D",
         "epoch": "SCREENING"},
        {"etcd": "TRT", "element": "Treatment", "tedur": "P84D",
         "epoch": "TREATMENT"},
        {"etcd": "FU", "element": "Follow-up", "tedur": "P28D",
         "epoch": "FOLLOW-UP"},
    ],
    arms={"PBO": ["SCRN", "TRT", "FU"], "XAN_LO": ["SCRN", "TRT", "FU"]},
    arm_names={"PBO": "Placebo", "XAN_LO": "Xanomeline Low Dose"},
)
ta = design.to_ta()
frames = design.domains()       # {"TE": df, "TA": df, ...}
findings = design.audit()       # P21-style conformance pre-check

    ArmStep ¶

    Bases: BaseModel

    One position of an arm path, with the TA values of that position.

    A plain ETCD string in a path is the short form of a step with no override. epoch replaces the element's epoch at this position (a crossover, an element that repeats). tabranch replaces the default Randomized to <arm> text, and tatrans gives the TATRANS rule.

    StudyDesign ¶

    Bases: BaseModel

    Typed aggregate of a study's trial design.

    arms maps each ARMCD to its ordered path of element codes — the per-arm element name/epoch/TAETORD repetition of raw TA rows is derived, never written by hand. A path entry is an ETCD string or an :class:ArmStep ({"etcd": ..., "epoch": ..., "tabranch": ..., "tatrans": ...}) for the TA values of one position. All fields accept plain dicts (Pydantic coerces), so a trial_design.yaml deserialises directly via :meth:from_yaml. An unknown key raises.

    TABRANCH defaults to Randomized to <arm> on the last element that every arm shares, or on the randomized_at element when it is given. A step's tabranch replaces that text: state the real rule when the branch is not a randomization.

    Each arm needs its protocol name in arm_names (TA.ARM); an arm with no name raises.

    References

    SDTMIG 3.4 TA (ARM is the protocol name of the arm); docs/adr/0052-a-trial-design-arm-needs-its-protocol-name.md.

    audit ¶

    audit(*, dm=None)

    Run the P21-style conformance pre-check over the derived domains.

    Two design checks come first: arms with the same path (FLEETTD04), and an element that repeats in one arm with no per-position epoch (FLEETTD05). An empty elements or arms section is an error, and an empty visits or criteria section a warning (FLEETTD09).

    Parameters:

    Name Type Description Default
    dm DataFrame | None

    Optional DM domain for cross-checking ARMCD assignments.

    		 None

    Returns:

    Type Description
    DataFrame

    pl.DataFrame: One row per finding (rule_id, severity, domain, message); empty when clean.

    Examples:

    Audit a design before export::

    findings = design.audit()
errors = findings.filter(pl.col("severity") == "error")

    to_mermaid ¶

    to_mermaid()

    Render the design as a Mermaid flowchart for a review document.

    Elements are grouped into epoch subgraphs; edges follow the arm paths, labelled with the ARMCD where the design branches (on the first edge for a single arm). The diagram is a review view: it carries ETCD, ELEMENT, TEDUR, the element epochs and the arm paths, but not ARM, TESTRL, TEENRL, TABRANCH, TATRANS or a per-position epoch. When :meth:from_mermaid cannot read the paths back (arms with the same path, a repeated element, a crossover), a warning says so. YAML (:meth:to_yaml) is the lossless round trip.

    Returns:

    Name Type Description
    str str

    A Mermaid flowchart TD document.

    Examples:

    Render for a design-review doc::

    print(design.to_mermaid())

    from_usdm classmethod ¶

    from_usdm(data, *, study_id=None)

    Build a design from a CDISC USDM (DDF) study definition.

    Maps the structural subset of USDM v3/v4 JSON: arms + epochs + elements + studyCells become the arm paths (with the epoch of each cell), encounters become visits, and eligibility criteria become TI rows. TI text comes from the v4 criterion item (or the v3 population criteria), with usdm:tag resolved through the syntax dictionary and XHTML removed. An identifier that starts with a digit takes an IN or EX prefix (SDTMIG 3.4 section 4.5.3).

    Epochs and encounters follow their previousId/nextId chain when it is complete, else the array order. An encounter's transition rules give TVSTRL and TVENRL; one warning counts the visits with no start rule. Only the first study design is mapped, with a warning when there are more. A study cell with an unknown armId, epochId or elementId raises.

    ponytail: schedule timelines, objectives/endpoints, and biomedical concepts are intentionally not mapped — extend when a consumer needs them.

    Parameters:

    Name Type Description Default
    data dict

    Parsed USDM JSON (the {"study": ...} wrapper or the study object itself).

    		 required
    study_id str | None

    Override for STUDYID; defaults to the study identifier whose scope organization type is "Clinical Study Sponsor", else the first study identifier.

    		 None

    Returns:

    Name Type Description
    StudyDesign StudyDesign

    Design with the mapped structural subset.

    Raises:

    Type Description
    ValueError

    When the version has no study design, a study cell holds an unknown reference, a criterion has no text or no inclusion or exclusion category, a tag cannot be resolved, or two criteria give the same IETESTCD.

    Examples:

    Import an OpenStudyBuilder / DDF export::

    import json
design = fleet.StudyDesign.from_usdm(
    json.loads(Path("usdm.json").read_text()),
    study_id="CDISCPILOT01",
)

    fleet.sdtm.tdd_audit ¶

    Trial Design conformance pre-check — a P21-style dry run, offline.

    Encodes the published, machine-checkable conformance rules that hit Trial Design domains hardest: the SD-series cross-domain structural checks and the FDA Technical Conformance Guide TS parameter profile (TS is the only rejection-level dataset — eCTD Technical Rejection Criterion 1734).

    Rule IDs reference the public Pinnacle 21 Community / FDA business rule identifiers so findings can be cross-checked against a real P21 report. Sources: FDA TCG TS parameter list (fda.gov/media/153632), PHUSE US Connect 2026 paper DS22, PharmaSUG 2023 DS-149.

    ponytail: a curated high-signal subset, not the full 100+ TDM rule catalog — fleet validate runs the CDISC Rules Engine for exhaustive coverage.

    audit ¶

    audit(
    *,
    te=None,
    ta=None,
    tv=None,
    ts=None,
    ti=None,
    dm=None,
    td=None,
    tm=None
)

    Cross-check Trial Design domains against published conformance rules.

    Every argument is optional — checks run only when the domains they need are present. Inputs may be DataFrames, LazyFrames, or the TDD collection models (TrialElements, TrialArms, ...). For each domain given, a Req variable (packaged SDTMIG 3.4 structure) that is absent or has a null or blank value is an error (FLEETTD08). TS coded values (TSVAL against its codelist, TSPARM against TSPARMCD) are not checked.

    Parameters:

    Name Type Description Default
    te Any

    Trial Elements domain.

    		 None
    ta Any

    Trial Arms domain.

    		 None
    tv Any

    Trial Visits domain.

    		 None
    ts Any

    Trial Summary domain.

    		 None
    ti Any

    Trial Inclusion/Exclusion domain.

    		 None
    dm Any

    Demographics domain, for ARMCD and ARM cross-checks.

    		 None
    td Any

    Trial Disease Assessments domain.

    		 None
    tm Any

    Trial Disease Milestones domain.

    		 None

    DataFrame

    pl.DataFrame: One row per finding with rule_id, severity (error/warning), domain, and message; empty (schema preserved) when everything passes.

    Examples:

    Pre-validate before shipping to P21::

assert findings.filter(pl.col("severity") == "error").is_empty()

    fleet.sdtm.tdd ¶

    Trial Design Domain (TDD) Pydantic models.

    Provides row models, collection models, constrained types, and an Epoch enum for the CDISC Trial Design domains: TE, TA, TV, TS, TI, TD, TM (protocol-reference) and SV, SE (subject-level).

    Each row model maps one record in the target SDTM domain and carries a _SDTM_MAP that translates Python-friendly field names to official CDISC variable names.

    Each collection model wraps a list of row models and enforces integrity constraints (uniqueness, ordering, FK references) at construction time via Pydantic @model_validator. The to_polars() method converts the validated collection into a pl.DataFrame with CDISC column names.

    Usage::

    from fleet.sdtm.tdd import TrialElement, TrialElements, Epoch

te = TrialElements(elements=[
    TrialElement(etcd="SCRN", element="Screening",
                 tedur="P14D", epoch=Epoch.SCREENING),
    TrialElement(etcd="TRT", element="Treatment",
                 tedur="P84D", epoch=Epoch.TREATMENT),
])
df = te.to_polars()

    from_schedule classmethod ¶

    from_schedule(
    schedule, *, anchor="RANDOMIZATION", window=None
)

    Build a visit schedule from day offsets relative to an anchor event.

    Visits are sorted by offset; VISITNUM is assigned 1..N in that order and VISITDY follows the CDISC no-day-zero convention (offset 0 → day 1, negative offsets stay negative). TVSTRL is rendered deterministically from the offset, anchor, and window, so rule text stays consistent across visits and study amendments.

    Parameters:

    Name Type Description Default
    schedule list[tuple[str, int]]

    (visit_name, day_offset) pairs; offsets are days relative to the anchor event (day 0).

    		 required
    anchor str

    Name of the anchoring milestone (e.g. "RANDOMIZATION").

    		 'RANDOMIZATION'
    window int | tuple[int, int] | None

    Allowed deviation in study days (no Day 0, as visit_map) — a single int for a symmetric window or a (before, after) tuple.

    		 None

    Returns:

    Name Type Description
    TrialVisits TrialVisits

    A validated collection ready for add_visits().

    Examples:

    Build a 12-week schedule anchored on randomization::

    tv_rows = TrialVisits.from_schedule(
    [("Screening", -14), ("Baseline", 0), ("Week 4", 28),
     ("Week 8", 56), ("Week 12", 84)],
    anchor="RANDOMIZATION",
    window=3,
)
tv = (
    fleet.frame(pl.DataFrame()).sdtm
    .fetch_structure("TV")
    .study_header("CDISCPILOT01", "TV")
    .add_visits(tv_rows)
    .to_frame()
)

    from_ctgov classmethod ¶

    from_ctgov(nct_id, *, timeout=30.0)

    Seed TS parameters from a ClinicalTrials.gov registration.

    Fetches the study record from the ClinicalTrials.gov v2 JSON API and maps the cleanly-derivable fields to TS parameters. The result is a starting point, not a submission-ready TS: dictionary-bound parameters (INDIC/SNOMED, TRT/UNII, PCLAS/MED-RT) are deliberately not guessed and must be added by the study team.

    Parameters:

    Name Type Description Default
    nct_id str

    ClinicalTrials.gov identifier (e.g. "NCT01234567").

    		 required
    timeout float

    HTTP timeout in seconds.

    		 30.0

    Returns:

    Name Type Description
    TrialParameters TrialParameters

    Collection with one row per derivable parameter (repeating parameters such as FCNTRY get incrementing TSSEQ).

    Raises:

    Type Description
    HTTPError

    When the NCT ID is unknown to the registry.

    Examples:

    Seed TS from the registry, then extend and build::

    ts_rows = TrialParameters.from_ctgov("NCT00048217")
ts = (
    fleet.frame(pl.DataFrame()).sdtm
    .fetch_structure("TS")
    .study_header("CDISCPILOT01", "TS")
    .add_parameters(ts_rows)
    .to_frame()
)

    to_polars ¶

    to_polars()

    Convert validated parameters to a Polars DataFrame with SDTM names.

    A TSVAL over 200 characters is split at a word boundary into TSVAL, TSVAL1, ..., TSVALn (SDTMIG 3.4 TS assumption 8). The space goes to the start of the next piece, so the pieces joined give the source text. A word over 200 characters is cut at 200.

    Returns:

    Type Description
    DataFrame

    parse_trial_design ¶

    parse_trial_design(mermaid_text)

    Parse a Mermaid flowchart into TE and TA collections.

    Each subgraph ID[TITLE] is an epoch; each node inside it is an element (ETCD["Element name<br/>P14D"]); each path from the start node to an end node is an arm, named by the last |ARMCD| label on its edges. A title that is not a C99079 term is kept, upper case, as a sponsor epoch, with a warning. %% comment lines are skipped.

    The diagram carries ETCD, ELEMENT, TEDUR, EPOCH and the arm paths. It does not carry ARM, TESTRL, TEENRL, TABRANCH or TATRANS, and it cannot carry a crossover or an element that repeats in one arm: YAML is the lossless round trip.

    Parameters:

    Name Type Description Default
    mermaid_text str

    A Mermaid flowchart TD string.

    		 required

    Returns:

    Type Description
    tuple[TrialElements, TrialArms]

    tuple[TrialElements, TrialArms]: Validated collections ready for add_elements() and add_arms().

    Raises:

    Type Description
    ValueError

    On an empty diagram, a line of an unknown form, a node outside a subgraph, an unlabelled fork, a cycle, a node with no edge, more than one start node, or two nodes or two arms that give the same code.

    Examples:

    Parse a simple 3-element design::

    flowchart TD
    subgraph SCR[SCREENING]
        SCRN["Screening<br/>P14D"]

    fetch_structure ¶

    fetch_structure(
    domain,
    *,
    ig_version="3-4",
    save_to=None,
    define_path=None
)

    Query the CDISC Library for domain's IG structure.

    When define_path is given the domain variables (including core) are read from the define.yaml first; if the domain is not found the method falls back to the online CDISC Library.

    When save_to is given the fetched metadata is cached as YAML; on subsequent calls the cache is read instead of hitting the API.

    SDTMIG 3.4 structures for the nine TDD domains (TE, TA, TV, TS, TI, TD, TM, SV, SE) ship with Fleet, so the default flow needs no network access and no API key; the CDISC Library is only queried for other domains or IG versions.

    Keeps the IG metadata on the namespace and compares it with the static Pydantic model; each difference gives a warning. The requested domain is kept too: study_header and the add_* verb must name the same domain.

    Parameters:

    Name Type Description Default
    domain str

    SDTM domain code (e.g. "TE", "TA").

    		 required
    ig_version str

    		 '3-4'
    save_to str | Path | None

    Optional path to cache the fetched YAML. A cache that holds another domain or IG version raises.

    		 None
    define_path str | Path | None

    Optional path to a define.yaml. When provided, domain metadata is extracted from the spec (offline) before falling back to the CDISC Library API.

    		 None

    visit_map ¶

    visit_map(
    target_num,
    target_name,
    *,
    date_col,
    planned_visits,
    ref_date=None,
    tolerance=None
)

    Map raw visit dates to planned visits from TV, by nearest study day.

    Use it only when the CRF does not collect the visit: it never replaces a collected VISITNUM. For each row, the verb takes the planned visit whose VISITDY is nearest to the actual study day (from date_col and ref_date), within the optional tolerance window. The distance is the difference of the study-day numbers, as abs(SVSTDY - VISITDY) in a SAS program: across the missing Day 0, Day -1 is 2 days from VISITDY 1. Ties resolve to the earlier VISITNUM. When TV has ARMCD values, a row only takes a visit of its own arm or a visit with a blank ARMCD.

    A dated row outside every window is an unscheduled visit. It gets the VISITNUM of the last planned visit on or before its study day plus .1, .2, ... in date order within the subject, and the VISIT UNSCHEDULED <VISITNUM>. A row with no study day gets a null. One warning gives both counts. With DOMAIN SV, one warning gives the USUBJID + VISITNUM keys that repeat.

    With no tolerance, every dated record takes the nearest planned visit, however far it is, so no record is unscheduled (ADR-0035). One warning then gives the count and the largest distance.

    Parameters:

    Name Type Description Default
    target_num str

    Name of the output VISITNUM column. An existing column of that name is replaced.

    		 required
    target_name str

    Name of the output VISIT column. An existing column of that name is replaced.

    		 required
    date_col str

    Column containing the actual visit date (ISO 8601 string).

    		 required
    planned_visits TrialVisits | DataFrame

    A TrialVisits collection or a DataFrame with VISITNUM, VISIT, and VISITDY columns (and optionally ARMCD).

    		 required
    ref_date str | None

    Column with the reference date for the study day. When it is not a column of the frame, it is read from the pinned DM, as study_day() does. When None, the frame must hold the study day in a VISITDY column.

    		 None
    tolerance dict[str, int] | None

    Optional {"before": n, "after": n} window in study days, boundaries inclusive: the actual study day may precede the planned VISITDY by up to before and follow it by up to after.

    		 None

    Returns:

    Name Type Description
    Self Self

    The namespace with target_num and target_name appended.

    Raises:

    Type Description
    DerivationError

    When date_col or ref_date cannot be found, when TV has arm-specific visits and the frame has no ARMCD, or when an unscheduled number would repeat a planned VISITNUM or reach the next whole number.
    References

    SDTMIG 3.4 SV and TV: USUBJID + VISITNUM is the SV key, VISITNUM is Req, a null TV ARMCD means all arms. The decimal number of an unscheduled visit is a sponsor convention (the CDISC pilot uses UNSCHEDULED 5.1); see docs/adr/0035-visit-map-numbers-an-unscheduled-visit.md.

    Examples:

    Map subject visits to planned visits::

    sv = (
    raw_visits.sdtm
    .assign("DOMAIN", value="SV")
    .assign("USUBJID", source="subject_id")
    .date("SVSTDTC", source="visit_date")
    .pin("DM", dm)
    .visit_map("VISITNUM", "VISIT",
               date_col="SVSTDTC",
               planned_visits=tv_rows,
               ref_date="RFSTDTC",
               tolerance={"before": 3, "after": 3})
    .to_frame()
)

    epoch_assign ¶

    epoch_assign(
    target,
    *,
    date_col,
    epoch_ranges=None,
    se=None,
    subject_col="USUBJID",
    same_day="by_class"
)

    Assign EPOCH based on date ranges or per-subject SE intervals.

    With epoch_ranges, each entry maps a study-level date interval to an Epoch value; the first matching range wins. With se, the subject's own element intervals drive the assignment: for each row, the epoch of the SE record whose [SESTDTC, SEENDTC] interval contains the date (SDTMIG 3.4: EPOCH of the start or collection date/time). A blank or null SEENDTC is open-ended; an element whose dates are partial is skipped, with a warning.

    On a transition date, where one element ends and the next starts, the time decides when the record and the boundary both have one. When one of them has no time, same_day decides, and one warning gives the count and the rule:

    • "by_class" (default): a Findings date (--DTC) takes the earlier element, an Events or Interventions date (--STDTC) the later one. Any other date_col name raises.
    • "earlier": the element that ends on that date.
    • "later": the element that starts on that date.

    No guidance fixes this case, so state the rule in the SDRG.

    Parameters:

    Name Type Description Default
    target str

    Name of the output EPOCH column.

    		 required
    date_col str

    Column containing the date to classify.

    		 required
    epoch_ranges list[dict[str, str]] | DataFrame | None

    A list of {"start": date, "end": date, "epoch": str} dicts, or a DataFrame with those columns.

    		 None
    se DataFrame | LazyFrame | None

    An SE domain frame with USUBJID, SESTDTC, SEENDTC, and EPOCH columns. Mutually exclusive with epoch_ranges. EPOCH is Permissible in SE: an SE with no EPOCH raises.

    		 None
    subject_col str

    Subject key used to join se (default "USUBJID").

    		 'USUBJID'
    same_day Literal['by_class', 'earlier', 'later']

    The rule for a record with no time on a transition date (with se only).

    		 'by_class'

    Returns:

    Name Type Description
    Self Self

    The namespace with target appended.

    Type Description
    ValueError
